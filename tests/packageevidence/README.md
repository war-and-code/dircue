# Syft package evidence fixtures

`fixtures/syft-1.52.0.json` was generated by the official Syft 1.52.0 macOS arm64 binary against the small inputs in `fixtures/input`. It contains six package observations, fifteen relationships, and three files. The .NET inputs exercise lockfile resolutions and built application dependency manifests. The Java input exercises an outer JAR and a nested JAR. Package names and archives are synthetic.

`fixtures/provenance.json` records the upstream version, release commit, schema, verified archive and executable hashes, command, input hashes, and report transformations. Two unused default cache paths were replaced before retaining the report. No package restore or build was run; remote enrichment was disabled by Syft's recorded configuration. The importer itself never invokes Syft.

The supported native schema is exactly [16.1.10 from Syft 1.52.0](https://github.com/anchore/syft/blob/v1.52.0/schema/json/schema-16.1.10.json). Importing a supported subset is not full validation of every upstream metadata extension. Metadata outside the allowlist is retained by digest, and original relationship types and directions are preserved. Unknown relationship types or unresolved endpoints make the imported evidence partial. Successful import does not establish that Syft completed every cataloger: `coverage.provider_scan` remains `unknown`.

Source identity is unknown unless a caller supplies a trusted binding between the exact report SHA-256 and the selected source identity. Such a binding is an attestation supplied by the caller; the importer cannot independently reconstruct when or against which checkout Syft ran. A directory source ID is not a content snapshot. Mismatches withhold project IDs. Explicit root mapping is required, and incomplete project discovery also withholds project IDs. Nested archive contents, conflicting access paths, and external coordinates remain separate from ordinary project ownership. Raw provider paths and arbitrary metadata are omitted from serialized output.

Run the package checks from the repository root:

```sh
go test -race ./pkg/packageevidence
go vet ./pkg/packageevidence
go test ./pkg/packageevidence -run '^$' -bench BenchmarkImportSyftFixture -benchmem
```

The benchmark reads the fixture before timing and measures import only, including JSON checks, digesting, extraction, and sorting. It does not measure Syft execution or filesystem profiling. Tests also exercise malformed and trailing JSON, duplicate keys and identities, count/byte/depth limits, cancellation, unsupported schemas, stale bindings, ambiguous project roots, incomplete inventories, untrusted text, and nested archive evidence.

Default limits are 16 MiB, 20,000 packages, 50,000 relationships, 50,000 files, and 100,000 locations. Explicit library limits have hard ceilings of 128 MiB, 100,000 packages, 250,000 relationships, 100,000 files, and 250,000 locations. JSON nesting is limited to 64 levels and two million value tokens. Limit or parse failures return no report. These are input limits, not a guarantee of a process-wide RAM ceiling.
