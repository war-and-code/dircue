# Ranked hotspot handoff

The order below prioritizes actionable product cost on the measured monorepos. It is not a sum across scenarios. CPU tables filter stacks to `phase=scan`, but pprof's default percentages retain the whole capture denominator; they therefore should not be interpreted as percentages of only the retained samples. Heap tables are cumulative process allocations, including warmup/calibration and validation, and are attributed through concrete scanner callers. Repeated full-copy costs can overlap in caller trees. Delay profiles accumulate waiting across goroutines and are not wall-clock latency.

The score is Impact × Confidence / Effort on 1–5 scales. A score clears triage, not correctness or acceptance. Only rank 1 is proposed for this first experiment. Its syscall component is supported by the trace-derived syscall-delay profile: 2.69 s / 83.38% cumulative beneath chroot Open, with object traversal and blob reads as callers. [Trace syscall evidence](profiles/roslyn-all-trace-syscall-top.txt). These trace profiles carry embedded symbols and must be rendered without re-symbolizing against the test executable; doing the latter produced incorrect function labels and was corrected before interpretation.

## Hypothesis ledger

- **Repeated packfile setup is material — supports.** CPU and allocation stacks independently converge on `ObjectStorage.packfile`, `ObjectPack`, filesystem path resolution and `NewScanner`/`NewReaderSize`. Same-host CLI metadata scans already spend 1.27 s on Spring and 3.97 s on Roslyn. This is the strongest opportunity.
- **The host is dominated by physical disk bandwidth — not established.** Warm CLI runs preserve block-I/O/fault counters, while CPU/trace show many filesystem calls. Those facts do not identify actual disk service time; macOS counters may be incomplete. No cold-cache or device-level I/O experiment was run.
- **More workers alone will fix Git scans — unsupported.** Object mutex and scheduler costs are material. There is no controlled worker-scaling experiment, and cache safety forbids removing the lock casually.
- **Large XML requires reading all nominal bytes — rejects for these workloads.** The real 2 GiB directory produces language results in a 28.70 ms median and optional combined analysis in 176.50 ms with bounded readers. Full-corpus bytes/sec is a logical normalization only.
- **Model or regex work is the first target — not supported by this ranking.** It has measurable allocations (Spring `regexp.get` 5.55%) but repeated Git storage construction is larger and has a narrower potential behavior-preserving intervention.

## Rank 1 proof obligations

Preserve report ordering, tie-breaking, language bytes, selected file inventory, warning/error classification, optional-module output and source revision semantics. No floating-point or RNG change is intended. Keep the existing bounded object threshold and object mutex. Close retained storage on failed snapshot construction and all Scan/Inspect returns after readers finish. Verify cache eviction beyond capacity, lazy large-object readers, malformed objects, linked worktrees and alternates. A cache insertion failure must close a newly opened packfile that has not entered the cache. Do not propagate cached-descriptor options into temporary alternate stores without adding their ownership model.

Require exact baseline/candidate JSON equality on every repeated CLI pair, focused lifecycle tests, existing regression suites and race checks, then interleaved same-host latency/RSS measurements. A warm diagnostic baseline alone cannot accept an optimization. Reprofile after the single lever because hotspot shares will change.
