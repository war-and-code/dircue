# ASCII lexer rule subsets

This historical candidate passed the maintained-library suite and all 3,388 actual Ruby ordered-token and language comparisons. Full-content and prefix paired library measurements and managed regeneration are complete. Later release checks are recorded in the [final validation bundle](../release/results/final/README.md). RC1 binaries remain preserved.

## Evidence and scope

The fresh identifier profile retains tokenizer CPU at 59.77% and capture matching at 57.76%, with the next subset opportunity scored 8.3 in `tests/profiling/HOTSPOTS.md`. The accepted identifier fast path remains byte-for-byte unchanged. This experiment changes one mechanism: which ordered regex branches are compiled into the lexer selected for an initial ASCII byte. It does not add whitespace shortcuts or alter rules, actions, model, line selection, storage, or classifier scoring.

## Conservative selection

Each existing rule is parsed with `syntax.Perl`, simplified, and compiled using Go's `regexp/syntax` package, matching `regexp.Compile`'s parsing semantics. Walk the compiled program's epsilon closure from `Start`, with visited instruction IDs to terminate cycles:

- Alternation follows both successors; capture, no-op and empty-width instructions follow their successor. Ignoring empty-width constraints can add candidates but cannot remove a matching candidate.
- Rune instructions contribute their matching ASCII set, including case folding. Single-rune and wildcard instructions are handled explicitly.
- A reachable match instruction makes the rule eligible for every byte, preserving nullable rules. Failed branches contribute nothing. Parse/compile errors, unexpected instructions or unsupported instruction metadata conservatively retain every byte.

For each ASCII byte, retain eligible rules in their original declaration order, and compile the same anchored named-capture expression with `Longest`. Variable-length byte masks are interned within each lexer rule list, avoiding fixed rule-count limits. Original rule IDs are used when constructing capture names, preserving identity despite smaller capture vectors. The final candidate does not retain a separate ID slice: tests recover IDs from those capture names. Empty/full masks and every non-ASCII first byte use the original full lexer. Subset choice occurs after the unchanged identifier shortcut.

## Equivalence argument

If a rule can match a nonempty input beginning with ASCII byte `c`, it either has an epsilon-only matching path or its first consumed rune is `c`. The conservative analysis includes the rule in both cases. It may retain impossible rules, which cannot win a match. Removing only impossible rules leaves the same longest matching extent; preserved declaration order leaves the same original winning rule on equal extents. Regex bodies, action metadata and the action loop remain unchanged, so the emitted tokens, state transitions and next byte are identical by induction.

- Ordering preserved: same original rule ID and consumed extent at each step; same action dispatch and token sequence.
- Tie-breaking unchanged: surviving branches retain declaration order and the existing `Longest` policy. Full-reference decision tests compare original rule IDs, not subset-local positions.
- Floating-point: identical code and accumulation order; no classifier change.
- RNG: no production randomness; generated tests use fixed seed 97002.
- Limits: unchanged 100,000-byte tokenization cap, 16-byte emitted-token cap, classifier prefix policy, NUL/string termination and malformed UTF-8 fallback.
- Golden outputs: all 3,388 actual Ruby ordered token sequences and labels match, with zero reference errors. The focused lexical reference tests and full maintained-library suite also pass.

## Executed correctness checks

Commands, first run in the isolated fork and then against final candidate source with `GOTOOLCHAIN=go1.26.6 GOWORK=off CGO_ENABLED=0`:

```text
go test ./internal/tokenizer -count=1
```

The suite passed. The reported test duration is not an accepted performance measurement. New tests include:

- Every initial/second-byte pair in both lexer states, including malformed UTF-8 and NUL, comparing original rule IDs and exact consumed lengths against the unchanged full regex.
- Subset interning checks and identity fallback for all non-ASCII initial bytes.
- Future regex constructs: nullable/nested repeats, captures, zero-width anchors/boundaries, inline case flags, Unicode-to-ASCII folding, wildcard modes, empty classes, no-match grammars and nullable-only grammars.
- Ninety-two-rule grammars to exercise masks and IDs beyond 64 rules.
- Ten thousand deterministic generated byte inputs against full lexical decisions and the frozen RC1 ordered-token loop, plus whitespace/state/token/input-cap boundaries.

Prior identifier tests and their RC1 frozen oracle also pass in the same run. That oracle shares the unchanged rule declarations; the independent actual Ruby gate additionally validates the complete pinned sample population. Future grammar changes must also recheck the retained identifier shortcut's separate assumptions.

## Startup and resource risk

Subsets are compiled eagerly and are immutable after initialization. There are no lazy locks or runtime regex reconfiguration. Every distinct mask adds a regex program and capture metadata; deriving masks also allocates temporary parse/program structures. This can increase cold process startup, initialization allocations and retained heap even if warm matching improves. Mask interning bounds redundant compilation but does not establish that overhead is acceptable.

Measure fresh-process wall/CPU/RSS as well as warm API counters on the same full/prefix corpus, with immutable baseline binaries and unchanged input receipts. Scanner `first-scan` timing and its CPU profiles exclude package initialization, so they cannot alone evaluate this risk. Profile the result before considering another optimization. Reject any semantic mismatch or unacceptable regression within the measured scope.

## Measured result

The [audited measurements](results/lexer-subset-opt2/README.md) retain twenty paired fresh processes per tool after three warmups, all raw samples, full labels, resource costs and environmental limits. Each process performs one measured complete corpus pass.

| Input | Official warm median | Maintained warm median | Official / maintained ratio (95% paired interval) | Whole-process ratio |
|---|---:|---:|---:|---:|
| Full content | 0.976746 s | 0.593149 s | 1.647× (1.632–1.654) | 1.499× |
| 128 KiB prefix | 0.920476 s | 0.531016 s | 1.733× (1.724–1.746) | 1.568× |

Allocated bytes per call fell to about 11,800 bytes versus the official library's 20,700–20,800 bytes, while allocation counts remain higher: about 166 versus 107. Peak process RSS is slightly higher for full content (106,900 versus 105,788 KiB) and lower for prefixes (94,572 versus 95,736 KiB). These are scoped library/process results; they do not establish universal repository CLI superiority or a separate Ruby oracle for truncated content.
