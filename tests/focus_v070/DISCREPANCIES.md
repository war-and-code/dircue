# Discrepancies and claim limits

No final conformance or performance receipt is committed with the harness source. Until a source-bound candidate is built and the runners complete, all empirical rows in `COVERAGE.md` remain `not run`.

Focused ownership is a static, nearest-manifest-directory rule. Metric equivalence therefore compares the focused report with the same authored paths in a full-root report. It does not claim equivalence with MSBuild evaluation, Python import resolution, runtime dependencies, compiler source membership or generated inputs.

The reverse query is checked for required membership rather than an exact affected-project set. Other parsed projects can legitimately name the same retained context. The receipt preserves the complete reported set for review.

Directory scope IDs bind request semantics, planner rules and the selected source kind. They are not live-directory content hashes. Fixture and performance input manifests provide the separate content identity.

The compatibility matrix is deliberately selected, not exhaustive. Earlier 0.6 release evidence covers a broader inherited CLI matrix. This harness adds release-specific focus evidence and retains raw captures for the commands it names.

Performance output is observational. Warm caches, host scheduling and JSON size affect results. The harness reports every sample, lane order, output digest, peak RSS and exact input identity, and makes no universal latency or memory claim.

Public monorepos can contain malformed test manifests or declaration evidence beyond configured limits. The performance runner permits an explicitly `partial` focus plan, retains its omissions and metric status, and does not turn that measurement into a complete-selection claim.
