# Dircue 0.8.0 release candidate

Dircue 0.8.0 connects a lightweight first look at a directory with more detailed inspection. It adds declared environment requirements, offline follow-up plans, and comparison of focused project and source-availability reports. All three are explicit operations; the default language path keeps its existing contract.

## Declared environments

```sh
dircue analyze environments --json /checkout
dircue analyze all --environments --json /checkout
```

Read project requirements without running a build or probing installed tools. The report separates language minimums, runtime constraints, toolchain preferences, target frameworks, platform targets and project SDK references. For .NET projects, it records the nearest selected `global.json` for a modeled invocation from the project directory, including supported SDK version, roll-forward and prerelease declarations.

Different projects can require different environments without being in conflict. Supported numeric Python constraints are intersected within a project context; unsupported syntax stays unresolved. These observations do not establish buildability or resolve installed SDKs. Evidence and read limits are documented in [Declared environments](../ENVIRONMENTS.md).

## Follow-up plans from saved evidence

```sh
dircue analyze discovery --json /checkout > first-pass.json
dircue capabilities --json
dircue plan first-pass.json --module declarations --module environments --json
```

Save the report outside the inspected directory. The planner reads that report and the caller's requested questions or modules. It records supporting evidence, prerequisites, candidate quantities and uncertainties. Commands are structured argument templates with a source placeholder; they are never executed. No source tree, worker, executable search path or service is inspected during planning.

Plans are bound to exact report bytes and capability versions. Missing signals do not become instructions to skip inspection, and partial evidence is distinguished from reusable complete results. See [Follow-up planning](../PLANNING.md) for the supported questions and limits.

## Compare targeted reports

```sh
dircue compare before.json after.json --json
```

Saved reports from 0.7's focus and availability modes can now be compared offline. Primary project files, related projects, shared context and focused metrics remain separate populations. Changed selections or counting policies prevent misleading comparisons; partial coverage cannot establish a removal. Availability comparisons preserve acquisition and checkout boundaries.

Inputs through aggregate schema 1.7.0 are accepted. Environment and explanation comparison are explicitly unsupported; supported modules in those reports remain usable. Existing schemas and comparison contracts remain supported.

## Compatibility and review boundary

Environment reports use aggregate schema 1.7.0. Plans and capability descriptions have their own schemas. Existing commands retain their previous schemas, JSON shapes and process behavior; help text includes the new commands.

The new features do not expand language catalogs or structural grammars, install tools, fetch content, run repository code, or choose and execute a build. Performance and compatibility evidence is recorded in [candidate validation](0.8.0-validation.md).

This candidate is prepared for independent review. It has not been merged, tagged or published as a release.
