# dircue 1.5.0

Dircue 1.5.0 expands repository assessment with explicit project groups, local dependency structure, and static entry points. It keeps exact selected file and byte totals separate from what the available declarations can establish. Policy decisions remain with the caller.

```sh
dircue analyze all --assessment --source directory --json /content
```

The optional assessment reports filename candidates, parsed projects, and distinct roots by ecosystem and path role. Supported workspace and solution declarations retain their member counts, unresolved references, and coverage. Definite local dependency edges form an observed connected-project graph; directory layout and matching package names do not establish independent applications or deployable services.

Manifest interfaces and deployment declarations add entry-point names and supported project associations to the same invocation. Script bodies are omitted, nothing is executed, and coverage discloses that source-code entry-point inspection did not run. The catalog covers the existing declaration/deployment adapters rather than treating every language as equally understood.

NuGet contexts now separate candidate lockfile presence, ownership, and the result of the named direct-package-presence check. Supported literal custom lock paths, harmless shared inputs, version-only central package declarations, and confined imports can reduce uncertainty. Conditions, unsupported expressions or import models, shared package items, collisions, and limits remain explicit. This does not evaluate MSBuild, resolve package versions, or verify locked restore.

Assessment uses component version `1.1.0` and aggregate schema `1.10.0`; lockfile observations use provider `1.1.0`. Current readers also accept the earlier forms. [Compatibility notes](https://github.com/war-and-code/dircue/blob/v1.5.0/docs/COMPATIBILITY.md) list intentional changes to optional output. Legacy language commands, default aggregate analysis, and map semantics remain unchanged.

The test additions include hand-labeled mixed-ecosystem trees, exact-count checks under evidence limits, attribution counterexamples, and optional .NET SDK queries restricted to synthetic fixtures. Runtime analysis stays offline and works without Git, Syft, a .NET SDK, or package-manager execution. See [repository measurements](https://github.com/war-and-code/dircue/blob/v1.5.0/docs/ASSESSMENT.md) and [lockfile observations](https://github.com/war-and-code/dircue/blob/v1.5.0/docs/LOCKFILES.md) for supported evidence and limits.
