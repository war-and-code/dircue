# 0.6.0 candidate evidence

0.6.0 adds two opt-in capabilities: bounded file-format observations and population-aware structural hotspots. It also compares those saved observations offline. Existing commands remain the compatibility baseline.

## Source and contracts

The measured Go executable was built from clean commit `b4fb6f4849c6327c04a65318578d417f0b1bd2c7`, tree `e597fc2b3d8488874a1af701397eef4472cce23e`, using release optimization flags and `CGO_ENABLED=0`. Its reported version was deliberately set to **0.5.0** to compare complete existing report bytes; it is not a release binary.

[Build identity](../../tests/performance/v060_candidate/build-identity.json) retains SHA256 `0ec849e2950a7b7c8d4cd726dc2d8d55cacb6885ab5467a4eb6547e32712b35b`, the build command and all 321 local Go/module/embedded input hashes. The reference is the downloaded, verified Darwin ARM64 0.5.0 binary. Later evidence and documentation commits do not relabel the measured commit; runtime input hashes are checked separately.

The optional worker has its own binary and source identity. The [validation receipt](../../tests/performance/v060_candidate/validation-checks.json) records the existing optimized worker, final Rust source hashes and build-audit limits. This corroborates the local build; it is not a claim of an independently reproduced toolchain. Tagged native packaging provides separate distribution verification.

Reports use aggregate schema 1.5.0 only when formats or hotspots are requested. Existing profiling schemas remain unchanged. Format evidence does not establish file purpose or container integrity. Hotspots describe measured BCA function spaces, separated by language/grammar and clean/recovered syntax. Nested spaces can overlap; the metrics are not repository grades.

## Functional evidence

- All **278 released-CLI compatibility cases** matched raw stdout, stderr and exit codes against 0.5.0, with zero untested cases. This includes earlier commands and declaration/comparison cases. Help and version additions are recorded separately.
- The full Go race suite and vet passed. The final race invocation reused source-keyed Go test-cache results; the retained record identifies those cache hits.
- Native schema/import/self-comparison tests covered all **20 structural languages**, 21 fixtures, three additional zero-function populations, and earlier schema 1.2 per-file reports. These tests exposed and verified a fix for importing embedded provider JSON metrics.
- Independent native proofs passed **19 format checks** and **20 hotspot checks**. Format cases include misleading names, invalid Unicode, parser bounds, 4,097-file selection and a 32 MiB read budget. The hotspot corpus contains **1,315 functions** with high-valued late entries beyond the older 128-per-file and 1,024-report caps.
- The worker passed **22 Rust tests**. Final focused fuzz campaigns completed **1,257,389 format executions** and **1,139,202 hotspot decoder executions** without failure. These are bounded campaigns, not exhaustive proofs.
- The Python release-helper suite ran 62 tests: 60 passed and two explicit execution opt-ins were skipped. Separate compiled-command proofs exercised the native functionality. Receipt tests reject planted capture and accounting corruptions.

[Retained check provenance](../../tests/performance/v060_candidate/validation-checks.json) includes source, fixture, executable and original-log hashes, measured assertions and qualifications. Local paths and raw temporary captures are omitted in this derived export. Earlier failed development runs remain identified as superseded, rather than being counted as passing final checks.

## Existing commands and optional formats

Measurements used macOS ARM64 on an Apple M1 Max host with ten logical CPUs, eight file workers, a 1,000,000-entry tree limit, three warmups and ten measured repetitions per lane. Caches were warm; each round reversed lane order while keeping reference/candidate pairs adjacent. Project builds and tests were paused. Other desktop and background work remained active; there was no CPU, memory or cache isolation.

Wall time includes process startup and the timing wrapper. RSS is the operating-system peak resident-set measurement for the CLI. ## Optional hotspot cost

This separate experiment uses pinned committed source subsets: 40 Java, 40 C# and 40 Python files, the 21 grammar fixtures, and the authored 1,315-function corpus. It does not represent whole-repository structural performance. [Input identities](../../tests/performance/v060_candidate/structure-inputs.json) and [all samples](../../tests/performance/v060_candidate/structure-results.json) retain source hashes and selection. No corpus code is built or executed.

Each lane is a complete CLI invocation, including worker startup and the extra capability probe for hotspots. The harness checks one parse per analyzed file, measured populations, deterministic output and preservation of prior observations. Invalid spans can qualify the parent status; that exception is recorded explicitly.

Each lane had 3 warmups and 10 measured repetitions, with alternating pair order. The RSS statistic is not the simultaneous sum of core and worker memory and is not a process-tree memory cap. Hotspots reuse the parse but still add traversal, aggregation, serialization and capability-check work.

## Distribution gate

The release workflow requires real extracted core/worker tests on Linux and macOS AMD64/ARM64 and Windows AMD64. New format/hotspot proofs are retained within the existing release receipt, preserving 44 attached assets. Installed native wheel launchers also exercise formats; workers remain separate. Linux launcher execution uses glibc; musl wheels receive payload verification, not native musl execution.

The private repository and deferred PyPI publication remain unchanged. Check the tagged release receipts for the final packaged executable identities; local candidate evidence alone does not certify downloaded artifacts.
