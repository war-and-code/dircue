# 1.0.0 preparation: review entry points

This is a draft for adversarial review, not a published release or a claim that
1.0.0 validation is finished. The development version is `1.0.0-dev`. Start
from `codex/1.0.0-preparation`, based on released 0.8.0 commit
`121027f44f014ac8d0a003a451a04b080a5ffe88`.

## What changed

The installed CLI now exposes three explicit reference views:

```sh
dircue capabilities --guide
dircue capabilities --cli --json
dircue capabilities --schema profile --json
```

The guide covers workflows, resource/coverage distinctions, error recovery and
all 18 analyzers. The catalog traverses the actual Cobra command tree and adds
semantic restrictions, output families, source selection and exit meanings.
Fifteen named JSON Schemas can be exported as standalone documents with their
transitive resources bundled for offline validation. The original
`capabilities --json` remains the planner descriptor.

Help, spelling hints and saved-report diagnostics are more specific. Suggested
corrections do not run automatically. Plain plans now show inert JSON argv,
prerequisites and cost qualifications. Successful JSON contracts and exit 0/1
behavior remain compatibility targets. Fresh explanations now reject invalid
error policies and explicitly empty tree selectors consistently with other
analyzers, instead of reflecting long values or scanning a default source.

Git snapshots now reuse at most eight packfile descriptors, with explicit
ownership and cleanup. The existing object mutex and large-object threshold
remain. A maintained-fork fix closes a newly opened pack if inserting it into
the cache fails while evicting another pack.

Two schema corrections accept values already emitted by the tool: the legacy
directory-language string percentage `"NaN"` for attributed empty files, and
the partial focused-metrics marker needed to read those reports back. The exported
language schema also rejects undefined percentages for nonempty entries and
formatted percentages outside 0–100.

## Evidence and useful challenges

- [Performance experiment](../../tests/performance/v100_preparation/OPTIMIZATION.md):
  source-bound cache-only builds, exact output checks, all raw paired samples,
  absolute time/RSS and post-change profiles. Challenge descriptor lifetime,
  eviction, cancellation and failed initialization. Check that allocation,
  elapsed time and resident memory are not conflated.
- [Compatibility harness](../../tests/compatibility_v100/README.md): 278 inherited
  cases plus 41 focused/context cases, against a checksum-verified published
  0.8.0 executable. Intentional diagnostic changes and saved-report fixes are
  explicit exceptions, not output normalization.
- [Ergonomics audit](../../agent_ergonomics_audit/audit/HANDOFF.md): independent
  judgments, real CLI transcripts, eleven baseline-failing/candidate-passing
  regression checks, reviewer findings and fresh-agent tasks. Scores are
  subjective rubric assessments, not measured user-success probabilities.
- `internal/cli/capability_cli.go`, `capability_guide.go`, `diagnostics.go`,
  `planning.go` and `schema/export.go`: challenge discoverability, truthful help,
  conflicting selectors, malformed values, terminal controls, writer failures,
  offline schema resolution and accidental changes to ordinary startup work.
- `schema/partial_focus_roundtrip_test.go`: challenge valid producer round trips
  and malformed-marker rejection, including incomplete project ownership.

The cache-only experiment reduced paired median elapsed time by about 20–43%
across five selected Git workloads. The 2 GiB XML directory control showed no
material change. ASP.NET optional analysis used about 0.9% more median peak RSS;
the other lanes used slightly less. These are warm-cache measurements on one
shared macOS host, with 20 measured pairs per lane. They are not universal
speedup claims or reliable extreme-tail estimates.

## Reproduction and release boundaries

Local validation passed the full race-enabled Go suite, vet, 319 compatibility
cases (305 exact, 12 reviewed diagnostic improvements, two saved-report fixes),
and all eleven audit regressions against both binaries. The integrated candidate
also stayed within 1% of the cache-only candidate's paired median time on three
control workloads. See the source-bound
[validation receipts](../../tests/compatibility_v100/results/local-validation.json).

```sh
go test -race ./...
go vet ./...
python3 third_party/update_go_git.py --check
go build -trimpath -o .cache/review/dircue .
.cache/review/dircue --version
.cache/review/dircue capabilities --guide
```

The compatibility build deliberately overrides its version to `0.8.0` to
isolate behavior from provider-version metadata. It must not be distributed
as the release binary. The isolated performance binary also excludes the CLI
changes; integrated checks are recorded separately.

The native structural worker is unchanged. No new analyzer, automatic external
execution, telemetry, network lookup, or repository configuration policy is
introduced. Git alternates, bare repositories, SHA-256 stores and parent-root
discovery retain their documented support boundaries; see
[#66](https://github.com/war-and-code/dircue/issues/66). Legacy single-file JSON
has no bundled schema yet, and the CLI catalog discloses that gap.

Draft CI runs the inexpensive preflight. Before release, the reviewed commit
still needs ready-for-review multi-platform CI, current conformance checks,
release packaging and installed-artifact verification. No release, tag or
public-visibility change is part of this handoff.
