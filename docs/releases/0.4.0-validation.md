# 0.4.0 candidate evidence

This report compares the candidate with released 0.3.0. Release gates are tracked
separately from earlier development experiments: a successful earlier binary does
not validate later source changes automatically.

## Changes from 0.3.0

0.3.0 added project declarations, content composition, and optional per-file
structural analysis. 0.4.0 adds six independently useful capabilities:

| Question | 0.3.0 | 0.4.0 addition |
| --- | --- | --- |
| What files are here before reading source content? | Language analysis or project/composition scan | Metadata-only discovery, including non-code and vendor candidates |
| How are declared .NET projects connected? | Reference declarations and target presence | Components, cycles, and degrees over explicitly defined edges |
| Can an existing package inventory be associated with projects? | No import command | Bounded native Syft JSON import with explicit source binding and mapping |
| Can callers add their own factual observations? | Compiled detector interface | Explicit bounded JSON rules over names, paths, and literal contents |
| Which package sources are declared? | Configuration filename candidates | Supported NuGet/npm declarations, sanitized origins, syntax and coverage qualification |
| Where are function-level structural measurements? | Optional per-file metrics | Bounded function-space entries with source spans and hashes, reusing the parse |

The new commands and report fields are opt-in. Semantic resolution, effective
builds, report comparison, incremental scans, broader registry adapters, and
a uniform plugin registry remain future work.

## Candidate gates

- Integrated Go race tests and vet passed after registry integration, with the
  actual function-capable native worker enabled.
- The final comparison binary passed all 209 exact 0.3.0 cases. The current
  native worker also passed 67 default-protocol comparisons, 21 breadth requests,
  function counterexamples, and CLI checks. All 280 recorded Go/build inputs
  matched the current candidate after these checks.
- [Composed-module checks](../../tests/compatibility_next/composition/README.md)
  passed with all eight optional modules requested together and five schema
  combinations, using the same comparison binary and native worker.
- The ready-for-review PR must pass the full CI matrix, including five native
  packaged-worker function checks, before merge.
- Release assembly must validate the tagged source, every platform's packaged
  executables, wheel contents, notices, checksums, and freshly downloaded assets.
  The new manual draft-release workflow has not yet completed its first GitHub run.

This is a candidate report. The outstanding gates above prevent a release-readiness
claim until their receipts have been reviewed.

## Performance and optional costs

The final candidate passed 100 measured ordinary-command runs against 0.3.0
over Cobra, Spring, Roslyn directory/Git, and a 2 GiB XML-plus-project fixture.
All output matched. Median timing changes ranged from −1.5% to +3.6%; median
peak-RSS changes ranged from −2.9% to +4.4%. These warm-cache, one-host samples
did not establish a persistent default-path regression or a meaningful speedup.

A separate 60-run campaign measured explicit registry inspection. Roslyn read
its two admitted configurations (3,514 bytes) and added about 26 ms to the
project scan median. The XML fixture had no registry configuration reads, but
adding the module increased median peak RSS by 8 MiB (12.2%). All five pairs
increased; the cause is not established. Non-configuration XML files do not acquire registry readers or retain
configuration content. This optional cost is retained
rather than described as zero overhead.

See the [final-candidate measurements](../../tests/performance/v040_candidate/README.md)
for raw samples, source identities, scope and verification.

## Retained development evidence

| Evidence | What it establishes | Limits |
| --- | --- | --- |
| [Compatibility suite](../../tests/compatibility_next/README.md) | 209 raw stdout/stderr/exit comparisons with released 0.3.0; default native behavior across 20 languages | Recorded binaries and cases, not every possible input |
| [Ordinary-path measurements](../../tests/performance/default_paths/README.md) | 100 measured runs and 20 Roslyn follow-up runs, all reports equal to 0.3.0 | Earlier rules/decoder candidate; warm cache, one host, timing variance retained |
| [Discovery](../../tests/discovery/README.md) | Seven cases including real Java/.NET trees and 2 GiB XML; small manifests remain visible | Three-sample diagnostic measurements, not universal speed claims |
| [Project graphs](../../tests/projects/graph/README.md) | Independent graph oracles, long chains/cycles, and pinned Roslyn/ASP.NET declarations | Supported static .NET reference graph, not evaluated builds |
| [Package import](../../tests/packageevidence/README.md) | Actual Syft fixture, bounded decoding, source association, fuzz and corpus measurements | Supported native schema, caller-provided source binding; no Syft execution |
| [Registry declarations](../../tests/registries/README.md) | Pinned npm oracle, parser fuzzing, independent privacy/type/XML/cancellation review | Selected supported configuration syntax; qualified identifiers may disclose internal names |
| [Function evidence](../../tests/functions/README.md) | Actual native output, hand-marked spans, recovery/caps, deterministic coverage | Provider semantics and supported grammars, not quality or semantic correctness |
| [Function decoder optimization](../../tests/functions/decode-performance/README.md) | 26.3% lower median decoder time and 29.9% fewer allocated bytes on a 128-entry fixture | Development implementation comparison; no whole-CLI or peak-RSS claim |
| [Importer field tables](../../tests/packageevidence/field-table-performance/README.md) | 6.41 MiB less allocation per 20,000-package import; cold-path and malformed cases retained | No meaningful speed or RSS improvement claim |
| [Rejected capacity change](../../tests/packageevidence/import-performance/README.md) | A candidate optimization increased malformed-input median RSS by 14.18% and was not merged | Negative experiment preserved; not current runtime behavior |
| [External resource limits](../../tests/resources/README.md) | 18 matching reports at 512 MiB with six simultaneous scans; deliberate 32 MiB OOM refusal | Earlier candidate; sampled memory is not exact peak or a universal memory guarantee |
| [Packaging checks](../../tests/release/README.md) | Contract tests, actual local packaged native checks, old-worker refusal | Final five-platform release checks still required |

Performance results must be read with their population, version, source selection,
limits, and binary identity. Discovery, function evidence, and package import
answer different questions; their times are not interchangeable.

## Work deliberately kept out

Bifrost and HTTP-declaration experiments inform future interfaces. Neither is
connected to the CLI. The HTTP experiment exposed false confidence in Python
receiver binding; those observations remain unresolved. No endpoint enumeration,
call graph, taint engine, automatic tool execution, repository scheduler, or
cross-repository atlas is part of 0.4.0.
