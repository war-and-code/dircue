# dircue 1.1.0

dircue 1.1 adds source-import evidence, launch declarations and local artifact references to the directory map. It also adds comparison exit codes for automation and exposes the existing parser and inventory bounds through the CLI. Analysis stays offline; inspected content is not executed.

```sh
dircue map --summary /path/to/checkout
dircue map --json /path/to/checkout > map.json
dircue map settings --json
```

Java/Kotlin, C#/Visual Basic and JavaScript/TypeScript imports can corroborate catalogued capabilities. Test-path and type-only imports keep their qualifications; they do not turn optional or peer dependencies into observed runtime dependencies. Maven dependencies explicitly declared with test scope remain visible in project and declaration reports without implying runtime capabilities in the map. These observations describe declarations and source syntax, not execution or installed packages.

The map records explicit .NET application output types, bounded Docker ENTRYPOINT/CMD declarations and Kubernetes CronJob schedules. Selected Maven system-path JARs and .NET HintPath DLLs can link a component to a file in the analyzed inventory. The new `artifact_reference` facts and `references_artifact` edges report file references; they do not identify packages or produce an SBOM. Missing, conditional and unresolved targets remain explicit.

Build relationships gain supported literal contexts from Compose, GitHub Actions and root Makefiles, local Terraform module sources and more careful Cargo attribution. Maturin binary interfaces use the supported Cargo target rather than the Python distribution name. Dynamic shell commands, unknown contexts and ambiguous ownership are omitted instead of being presented as verified links. Docker Bake remains outside the supported scope.

For automation, comparison exits are an explicit choice:

```sh
dircue map compare --json --exit-code before.json after.json
```

With `--exit-code`, unchanged exits 0, changed exits 1, uncertain exits 2, and handled errors exit 3 with a diagnostic. `--on-uncertain allow` uses the observed result while retaining the report's uncertainty. Without the option, successful comparisons still exit 0 and handled errors still exit 1.

Existing language commands keep their output contract. New map observations and local-artifact entries in project/declaration reports are intentional additions. Capability and deployable observer versions advance to 1.1.0; the map's schema version remains 1.0.0 under the additive compatibility policy. Older strict readers may reject new optional facts or the `references_artifact` enum value. See the [compatibility policy](https://github.com/war-and-code/dircue/blob/v1.1.0/docs/COMPATIBILITY.md) and [map guide](https://github.com/war-and-code/dircue/blob/v1.1.0/docs/MAP.md).

Validation includes exact comparisons with the published 1.0.1 executable, map regression gates, adversarial counterexamples and native archive/wheel checks. The richer map has a measured runtime cost on the tested large Java and .NET repositories; this release does not claim to improve every performance metric. Scores use selected, source-reviewed regression labels, not an independent accuracy estimate. The [measurement guide](https://github.com/war-and-code/dircue/blob/v1.1.0/tests/performance/v110_candidate/README.md) records the workloads, results and limits.

Release archives and Python wheels provide both `dircue` and `dirq` for the supported Linux, macOS and Windows platforms. The optional structural worker remains a separate download. After this version is published to PyPI, projects can pin `dircue==1.1.0` and install through ordinary `uv sync`; GitHub Release publication alone does not upload to PyPI. Wheels need Python 3.10 or later. Standalone archives do not require Python. See the [distribution guide](https://github.com/war-and-code/dircue/blob/v1.1.0/docs/DISTRIBUTION.md) for platform details.
