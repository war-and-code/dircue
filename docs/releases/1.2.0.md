# dircue 1.2.0

Dircue 1.2.0 adds optional, offline dependency context: selected lockfile associations, declared toolchain selectors, and Maven/Cargo package-source declarations. The language-only path and default aggregate analysis do not select these modules.

- `dircue analyze lockfiles --json` or `dircue analyze all --lockfiles --json` associates supported npm/NuGet projects with selected lockfiles and reports named, bounded declaration checks. npm checks root declaration tables in lockfile formats 2 and 3; NuGet checks observed direct package presence for supported `.csproj` contexts. A match does not establish a reproducible restore, graph consistency or lockfile freshness.
- `dircue analyze environments --json` also observes selected `.python-version`, `.node-version`, `.nvmrc`, `rust-toolchain` and `rust-toolchain.toml` files. Nested declarations and unresolved selectors remain qualified; no installed or effective toolchain is inferred.
- `dircue analyze registries --json` also reads selected Maven `settings.xml` and Cargo `.cargo/config` or `.cargo/config.toml` files. Credentials and URL paths are withheld. Configuration precedence and effective registry selection remain unresolved.
- Current environment reports identify selected Git trees with their exact object ID, while readers retain legacy 1.0.0 environment support. Saved aggregate reports reject conflicting sources for modules that reuse declarations. Ambiguous Maven fields, duplicate NuGet package IDs and unsupported Cargo configuration includes remain qualified rather than supplying certain evidence.
- Saved-report comparison and follow-up planning accept the new lockfile module. Environment comparison reports changes in retained declaration evidence, with provider and coverage qualifications.

Lockfile selection advances the aggregate profile schema to 1.8.0. Environment provider and registry rule versions advance to 1.1.0; explicitly requested reports therefore have updated metadata and scope even when no new supported files are present. Existing .NET SDK-selection inputs and npm/NuGet registry facts retain their meanings. Older strict consumers may need updating.

All inputs come from the selected directory or Git tree. These observers do not run package managers, builds or install scripts, contact registries, or inspect user/system configuration. They disclose bounds and missing or unsupported coverage. npm workspace ownership, custom NuGet lockfile path resolution, effective environment selection and merged configuration remain outside this release's claims. See the [lockfile guide](https://github.com/war-and-code/dircue/blob/v1.2.0/docs/LOCKFILES.md), [environment guide](https://github.com/war-and-code/dircue/blob/v1.2.0/docs/ENVIRONMENTS.md), [registry guide](https://github.com/war-and-code/dircue/blob/v1.2.0/docs/REGISTRIES.md) and [compatibility policy](https://github.com/war-and-code/dircue/blob/v1.2.0/docs/COMPATIBILITY.md).
