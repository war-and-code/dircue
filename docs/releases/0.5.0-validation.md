# 0.5.0 candidate evidence

0.5.0 adds two opt-in operations: static project declarations across six ecosystem
groups, and offline comparison of saved aggregate reports. This report separates
the measured runtime candidate from later documentation and release packaging.

## Capability changes

| Question | 0.4.0 | 0.5.0 addition |
| --- | --- | --- |
| Which workspaces and local dependencies are declared? | Detailed .NET/JVM readers; filename discovery elsewhere | Bounded npm, Go, Python/uv and Cargo readers alongside the existing readers |
| Which named interfaces are declared? | Some project and configuration observations | Supported script names, entrypoints, targets, build backends and toolchain requirements, with evidence and qualifications |
| What changed between saved profiles? | Consumers implement their own comparison | Offline module comparisons with explicit compatibility, coverage and observation identity |

Declaration reports use aggregate schema 1.4.0. The comparison format has its own
schema 1.0.0. Other profiling invocations retain their output contracts. The new
`compare` subcommand reserves that bare name; use `./compare` or `-- compare` to
profile a directory with that name.

These are static observations, not effective dependency resolution or proof that
a build works. The new report withholds script bodies and unsupported source
values, records conditional and unresolved relationships, and distinguishes a
present target from a resolved declaration. Comparison does not establish that two
reports describe the same repository. Partial or unrecorded coverage limits what
absence can mean. See [declarations](../DECLARATIONS.md) and
[comparison](../COMPARISON.md) for the supported subsets.

`4f32b22a54bdfb208d22a5227624baa1ef9c4178`, tree
`b5ae1fe778b0b4c51174d14b8110597ac6b43b08`, using Go 1.26.6 for Darwin ARM64,
`CGO_ENABLED=0`, and release optimization flags. Its version string was deliberately
set to **0.4.0** so the benchmark could compare complete existing report bytes
without masking version fields. It is a measurement executable, not a release

[Build identity](../../tests/performance/v050_candidate/build-identity.json)

equivalence separately. The baseline is the published Darwin ARM64 0.4.0 binary,
whose SHA256 is recorded in the same evidence set.

## Functional and compatibility checks

The final performance harness required byte-identical baseline/candidate output
for language-only and default aggregate commands on every corpus. It also required
unchanged existing aggregate observations when adding declarations, equal
standalone/combined declaration observations, and identical repeated outputs.
All 480 measured executions passed these checks. Corpus inventories and binary
hashes matched before and after measurement.

The patched candidate passed the full Go race suite and vet, and the 53-test
Python release suite with two optional checks skipped. Earlier development
validation included bounded parser/comparison fuzzing, adversarial manifest
limits and independent ecosystem oracles. Those earlier runs are not presented
as fresh fuzz campaigns against the patched executable. Python/uv expectations
include six offline metadata comparisons with uv 0.12.17. A copied synthetic
workspace also matched Cargo 1.85.0 offline metadata for membership, default
selection and inherited version/edition/minimum Rust version, without builds or
dependency fetching. Its original fixture/version/output hashes remain retained.
These checks do not establish complete package-manager emulation.

The private JSON Schema v5.3.1 copy defers optional validation initialization.
Earlier independent checks against the unchanged upstream package cover 75 schemas,
1,100 instance evaluations, 11 fresh-process initialization cases, concurrent
first use and ten historical reports. Source provenance and the patch are
reproducible and unchanged by the dependency update; the optimization does not
replace the untouched test oracle. The fresh race suite reruns its retained tests.

Hosted checks passed for the PR containing the measured runtime commit. GitHub
checks use its merge checkout; Linguist provenance records
`760b1d6c741aaafe3050f3f9499efa39d96db135` separately from local build `4f32b22`:

- [CI](https://github.com/war-and-code/dircue/actions/runs/35527155046): all six jobs, including Linux/macOS/Windows tests. Linguist had 404 passes, 16 documented expected differences and zero unexpected failures across 420 cases. Classification matched 3,388/3,388 pinned upstream samples, including 2,629 programming/markup samples. All six scc differential checks passed; parity retains the documented upstream raw-string counting limitation.

The final [241-case released-CLI comparison](../../tests/compatibility_v050/README.md)
passed all 241 cases with no untested cases: raw stdout, stderr and process status
matched the released reference. Version/help additions are recorded separately.
The fresh [declaration corpus](../../tests/declarations_corpus/README.md) passed
all 80 executions in one complete run, with no expectation errors. It used the

[Retained check provenance](../../tests/performance/v050_candidate/validation-checks.json)

hashes, and original receipt digests. It is a derived export; raw outputs and local

The corpus includes pinned OpenTelemetry Go, Pydantic AI and npm CLI workspaces,
with expectations authored from manifests before profiling. OpenTelemetry covers
29 Go modules; Pydantic AI covers six `pyproject.toml` manifests and five explicit
uv workspace members. The matrix exercises Git/directory selection,
standalone/combined declarations and one/eight workers. Pydantic AI remains
partial: 15 symlinks are omitted and one direct Git dependency source is withheld.
Dynamic versions are not invented.

The npm CLI cases check 16 root workspace members and local relationships within
473 candidate manifests. Its report remains partial: 471 manifests parse, two
fixture manifests are malformed, and unsupported fixture declarations retain
diagnostics. No selected files are omitted. Passing means the expected facts and
coverage agree, not that every manifest in the package manager's test suite is
valid. Earlier 56-, 16- and eight-run receipts belong to the previous candidate;
the final evidence uses the new complete 80-run receipt.

An actual-version 0.5.0 Darwin ARM64 archive and its matching wheel each passed all
13 declaration/comparison smoke checks over 12 manifests and six ecosystem groups.
The core was extracted from the archive. The wheel was installed into an isolated
virtual environment without a package index or dependency downloads, and its
console launcher was exercised. Archive, wheel, launcher and installed-core hashes
are retained with the source binding. This native check does not substitute for
the other platforms or final uploaded-release asset verification.

## Dependency check

The final candidate updates `golang.org/x/crypto` to 0.56.0 and `golang.org/x/mod`
to 0.40.0, with their required net/sync/sys/text dependency updates. A
[govulncheck 1.1.4 scan](../../tests/performance/v050_candidate/govulncheck.txt)
reported zero reachable findings and zero imported-package findings. One
module-only advisory remains, GO-2026-5932, for the unimported and unmaintained
`golang.org/x/crypto/openpgp` package; no fixed version is listed. This is a
bounded database-driven check, not a claim that the software has no vulnerabilities.
Private forks and internal copies also require their own source review.

## Existing-command performance

These measurements used one Apple M1 Max host with ten logical CPUs, macOS 26.5.2,
eight file workers, a 1,000,000-entry tree limit, three warmups and ten measured
repetitions per lane. Filesystem caches were warm; lane order reversed each round
with baseline/candidate pairs adjacent. Project builds and tests were paused, but
other desktop applications and unrelated background Python work remained active.
There was no cache eviction or CPU/memory isolation.

Added time is the difference between the combined declaration median and the
candidate's default aggregate median. The negative Express difference reflects
measurement variation; it does not mean additional work is free. Roslyn directory
mode added about 138 ms, or 4.27%, to the aggregate median. Standalone declarations
avoid classifying unrelated contents but still enumerate the selected population.

The XML fixture contains 128 regular files with 2 GiB of actual XML bytes. Its
standalone declaration report had zero candidate and parsed manifests. The
20.93 ms median measures enumeration and reporting without XML parsing; it is not
a throughput measurement for reading 2 GiB of file contents. The harness hashes
actual file contents outside the timed region to verify input stability.

## Saved-report comparison cost

A separate [Go microbenchmark](../../tests/performance/v050_candidate/comparison-bench.txt)
ran five process-warm replicates on the same M1 Max host with Go 1.26.6. Loading
and validating a synthetic 500-project report took 11.80–13.40 ms per operation
and allocated about 6.56 MB per operation. Comparing two loaded 500-project reports,
with 50 changed engine declarations, took 21.80–22.43 ms and allocated about
25.33 MB per operation.

Allocated bytes are cumulative allocations, not peak RSS. These function-level
measurements exclude CLI startup and, for comparison, input loading. They provide
a bounded cost example, not a speedup comparison or a prediction for every report.
The raw benchmark text and its source hash are retained separately from the CLI
performance samples.

## Retained evidence and release gates

[Results](../../tests/performance/v050_candidate/results.json) retain all measured
and warmup samples, stdout/stderr hashes, execution order, environment, coverage,
corpus identities and summary statistics. The six public Git checkouts are pinned
by commit/tree. Directory cases retain content-inventory hashes.

These public JSON files are **derived exports**, not byte-identical original
receipts. Their `public_derivation` fields record the original receipt SHA256 and
each transformation: replace absolute host paths with named placeholders, separate
the build identity and omit verbose timing diagnostics. Additional check receipts
retain their own source hashes and documented field omissions. Compressed raw
command outputs are not published because they contain local source roots; their
original hashes remain recorded. Numeric measurements and the
311 build-input hashes are unchanged. Earlier exploratory measurements are not
mixed into this final run. The [harness guide](../../tests/performance/v050_candidate/README.md)
describes reproduction and measurement limits.

Release assembly must separately validate the tagged source, archives and wheels,
all five native packaged declaration/comparison smoke receipts, installed-wheel
launcher checks, worker checks, notices, checksums and downloaded uploaded-asset
hashes. The expected 44 assets
include five new declaration smoke receipts; native wheel-launcher evidence is
embedded in the aggregate release receipt. Passing local candidate measurements
does not substitute for those packaging gates; their release receipts identify the actual
shipped executables. PyPI publication is not part of this release process.
