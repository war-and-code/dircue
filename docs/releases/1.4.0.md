# dircue 1.4.0

Dircue 1.4.0 adds an optional repository assessment: language statistics, selected files and logical bytes, manifest populations, declared project roots, local relationships, and supported lockfile associations in one JSON report. It works without Git or Syft and leaves policy decisions to the caller.

```sh
dircue analyze assessment --source directory --json /content
# Equivalent opt-in on the existing aggregate command:
dircue analyze all --assessment --source directory --json /content
```

The assessment component records scope and completeness for each measurement. Bounded example lists do not reduce exact file or manifest totals. Unparsed manifests, unsupported ecosystems, unknown associations, and parser limits remain visible. Project counts exclude configuration-only records and distinguish several manifests in one project directory from several project directories.

Supported npm v2/v3 shared workspace locks can be attributed to members when selected declarations establish a unique owner and the lock contains the member's own package entry. Each member's direct declarations are checked against that entry. Finding a lock somewhere above a project is insufficient. NuGet retains its passive checks and qualifications for shared or imported build inputs, conditions, ambiguous ownership, and custom lock paths. An observed association does not prove lockfile freshness, dependency resolution, or restore success.

An existing Syft report can enrich the same invocation through `--syft-report`. It is imported through the existing package-evidence module and cannot establish native manifest counts, project relationships, lockfile ownership, or completeness. Dircue does not run Syft, restore packages, evaluate build scripts, or generate an SBOM.

Profiles containing assessment use aggregate schema `1.9.0`; the component starts at version `1.0.0`. Help, the offline guide, schema exports, saved-profile comparison, and inert follow-up planning support the new module. Legacy language output, default `analyze all`, map semantics, and earlier `--lockfiles` behavior retain their contracts.

See [repository measurements](https://github.com/war-and-code/dircue/blob/main/docs/ASSESSMENT.md) for definitions, supported populations, source selection, and limits. This is a release candidate awaiting review; no release or publication is implied by these notes.
